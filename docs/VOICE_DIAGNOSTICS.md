# 每轮对话诊断与会话状态

适用：Mac 浏览器版，服务版本 8。入口位于页面下方 **每轮对话诊断 · 后台管理**。

## 怎么用

1. 刷新助手页面，点击「点击说话」，说一句完整的话，再结束并发送。也可以先用文字检查模型和播放。
2. 展开「每轮对话诊断 · 后台管理」，点击对应时间的一轮记录。
3. 查看「当前」阶段和耗时。完成、失败、没有有效问题、被打断分别显示；等待较久会提示可停止后重试。
4. 有问题先点「导出诊断」，再刷新或重启。可把导出的 JSON 发给开发成员排查。
5. 「清空已结束记录」只清理本页面已结束的记录，保留正在进行的轮次，不会删除记忆或声纹。

文字输入不采集音频，所以没有收音、语音转文字和声纹步骤。未开启声纹或自动朗读时，对应阶段不会假装执行。

## 阶段怎样理解

| 阶段 | 正在做什么 | 等待或失败时先看什么 |
|---|---|---|
| 打开麦克风 | 等待权限并启动采集 | 浏览器权限、系统输入设备、USB 连接 |
| 收音 / 断句与提交 | 接收语音，等待停顿或手动结束 | 是否真的说话、环境回声、是否仍在持续收音 |
| 语音转文字 | 本机识别讲话内容 | 输入是否有效、识别服务是否可用 |
| 声纹匹配 | 与已登记声纹对比 | 下方「声音识别诊断」中的有效语音、阈值、相似度和拒绝原因 |
| 共同记忆权限 / 指令处理 | 校验说话凭证与空间权限，处理查询或写入指令 | 是否登录、绑定档案、正确识别说话人，是否有权限 |
| 检索相关记忆 | 查找可使用的资料 | 所选档案／空间、记忆状态、可见范围 |
| 等待模型首段回答 | 请求已进入模型，尚未收到回答正文 | 模型是否就绪、远端连接、首次加载情况 |
| 生成回答 | 已收到首段文字，正在生成后续内容 | 模型服务是否中断；可点击打断 |
| 合成声音 | 将回答文字转成音频 | Mac 语音服务是否可用 |
| 播放声音 | 浏览器播放音频 | 浏览器播放权限、系统音量和实际输出设备 |
| 等待口头确认 | 共同记忆预览已播完，等待确认 | 说完整的确认句，或取消；后续录音会成为下一轮 |

页面阶段与服务端细分是两种观察视角：服务端耗时包含在页面阶段里，不能重复相加。唤醒模式的「收音 / 断句与提交」还包含自动提交与识别等待；进行中每约 1.2 秒查询服务端实际阶段。运行特别快的阶段可能直接显示为已完成。

“播放完成”只说明浏览器触发了播放结束，不能检测实体扬声器是否出声。打断后，页面立即停止旧轮次；已进入的语音识别等任务可能仍在收尾，最后一次服务端快照会明确标识这一点。

## 保存范围

- 页面内存仅保留最近 20 轮。刷新或关闭页面后消失，不写入浏览器持久存储。
- 服务端内存最多保留 128 个追踪，每个最多 64 个阶段，停止更新 30 分钟后过期；服务重启即清空。
- 导出包含随机轮次号、输入方式、时间、阶段、状态、耗时、固定提示代码，以及录音时长／有效语音时长／部分匹配数值。
- 不包含聊天正文、记忆原文、账号姓名、声纹向量、录音和 API Key。声纹具体档案名称仍在原有用户界面查看。
- 没有诊断记录列表的服务端公开接口；页面用不可预测的轮次号按需读取本轮内容。接口沿用仅本机与同源检查。
- 这是新增的逐轮诊断。原有最近 10 步声音识别面板及有界的 `.runtime/speaker-diagnostics.jsonl` 保持独立。

## 验证与边界

已验证：后端实时阶段查询、识别／模型／合成耗时、错误归属、并发隔离、内容排除和内存上限；前端录音到播放共用轮次、播放失败、录音权限失败、等待确认、打断、旧请求迟到与清空记录隔离。Mac 实际网页验证了本地模型回答、TTS、播放完成和停止，测试使用独立临时数据库。

仍需现场验收：ReSpeaker 真机收音、甲乙与未知说话人交替、扬声器回声、连续插话、USB 拔插。诊断功能帮助定位这些问题，不等于这些设备效果已达标。Windows 尚未完成实机验证。
