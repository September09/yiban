# 共同记忆备份与确认恢复

入口：共同记忆 → 登录空间账号 → 备份与恢复。适用于家庭或团队的单个完整空间。资料导入仍负责从聊天记录提取候选；这里读取的是忆伴导出的完整备份。

## 下载备份

选择需要备份的空间，管理员勾选“包含私密记忆、完整原文和历史”，点击“下载共同记忆备份”。导出不受记忆库筛选影响，包括：

- 全部记忆正文、状态及说明、事件日期、来源说明、创建与更新时间和版本。
- 成员角色、作者与修改人、可见成员及修改权限。
- 修改前后历史、已归档完整原文、原文摘录位置和新旧安排替代关系。

不包含账号口令或口令哈希、登录凭证、声纹、个人记忆、聊天记录、回答反馈与诊断记录。JSON 是未加密文件，含本空间私密资料和完整原文，请保存到可信位置，不提交到 Git。

## 预览并恢复

1. 在目标电脑先注册需要的本机空间账号；不需要沿用原口令。登录执行恢复的账号。
2. 选择 JSON 文件并点击“读取共同记忆备份”。查看记忆、历史、原文、依据、关联及成员数量。
3. 填写新空间名称。原管理员固定对应当前账号；逐一确认其他备份账号对应的现有本机账号。不同备份账号必须对应不同账号，避免权限合并。
4. 点击“预览恢复到新空间”。核对归属、角色、正文、状态、日期、可见范围和修改权限；可展开原文与历史查看。
5. 勾选资料与权限两项确认，再点击“确认恢复到新空间”。成功后自动进入新空间记忆库。

确认前不创建空间。恢复生成新的空间和记忆编号，沿用文件中的正文、状态、日期、历史、原文与关联，原空间继续保留。备份中的有效状态表示文件原有记录，不表示本次重新核实事实。历史账号会对应署名；仅原来的现任成员加入新空间，已移除的历史账号不会自动重新加入。

管理员仍可查看全空间资料；“全体成员”也包含以后加入的成员。指定可见恢复为对应后的账号，作者和管理员仍按现有成员规则执行。跨电脑恢复需要自己核对账号对应的实际人员。

## 重复、失败与取消

- 同一份完整内容、同一账号对应、同一新空间名称，已恢复过会提示现有结果；仅导出时间改变不影响判断。修改文件、对应或名称则可能创建另一份空间，不做跨备份正文合并。
- 预览与当前登录会话绑定，10分钟有效。修改名称、对应关系、选文件、切换空间或退出都会清理页面预览。
- 同一事务恢复空间、角色、记忆、历史、原文和关联；中途失败整批回滚。保存成功后的网络重试可返回同一结果；服务重启后的已完成确认也能识别。未完成预览在服务重启后需重新生成。
- “取消恢复”只放弃预览；已经确认创建的空间不通过此按钮撤销。

## 限制与实现

v1 JSON 最多24 MB、200条记忆、100个关联账号、10000条历史、200份原文，每份原文最多30000字；每个账号最多拥有20个空间。超限报错，不截断。仅导出系统已保存的文字依据，不包含原始 PDF、图片或 Word 文件。

当前只支持恢复到新空间，尚不支持合并到已有空间、覆盖当前空间、批量多个空间、定时备份、加密备份或导入批次回滚。单条误操作可用[回收站、历史恢复与替代纠正](SHARED_RECOVERY.md)。空间备份不包含回收站与独立恢复审计；先恢复需要备份的回收站记录再导出。索引是可重建的派生数据，不随备份传输。只恢复可信文件；内容哈希用于一致性校验，不是发行者签名。

业务数据继续存于 SQLite 主库；新增 shared_restores 表保存恢复去重凭据、原空间名称和账号对应。账号凭证继续使用本机原有账号库。服务端预览内容暂存内存，最多4份，确认后清理。

## 本轮验证

已完成10项隔离后端测试（含真实HTTP路由）：管理员导出、跨库账号映射、历史账号不重新入组、私密可见范围、原文与历史和替代链、损坏文件拒绝、预览不写入、取消／过期／跨会话拒绝、中途失败回滚、重复恢复及重启后重试。完整297项后端回归与页面逻辑检查通过。

浏览器使用虚构资料验证读取文件、账号对应、恢复预览、展开原文、双重确认及新空间记忆库；导出页面显示生成文件，并核对下载文件与源记忆一致。自动文件选择受扩展权限限制，改用系统文件选择框完成。未录音、播放声音或修改音量，真实资料不用于恢复测试。

## 资料批次扩展

新备份在v1格式中附加可选batches字段，包含在库记忆的导入批次、来源名称、初始版本与导入时间；恢复到新空间时同时映射账号和重建编号。旧文件没有该字段时按空批次处理。回收站、独立撤销审计和没有在库记忆的批次仍不包含在此空间JSON备份中。详情见[资料来源与导入批次](IMPORT_BATCHES.md)。
