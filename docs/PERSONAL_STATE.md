# 个人记忆状态与疑似冲突

入口：**个人记忆 → 选择档案**。本功能仅管理当前个人档案，不自动共享给家庭／团队。个人档案选择不是身份认证，适用于现有本机管理场景。

## 三种状态

| 状态 | 含义 | 查询行为 |
|---|---|---|
| 待核实 | 已保存，尚未核对当前是否适用 | 可以检索；回答提示尚待核实 |
| 有效 | 当前操作者已填写说明并标记有效 | 可用于当前问答；不是程序证明事实为真 |
| 过时 | 过去的情况，现已不适用 | 默认在检索和向量编码前排除；明确回顾时可查 |

原有记忆在升级后先按待核实处理，正文、编号、原时间和来源不改。更早历史记录的核实状态保持未知，不倒填成已核实或捏造旧状态。

可填写事件日期及状态说明。有效／过时状态必须有说明；日期只是辅助线索，不会按日期自动判断真假或自动过期。正文或事件日期改变后回到待核实，旧核实说明清空；请核对新内容后另行标记。

## 保存和改状态

1. 无冲突的新增待核实记忆、且无额外日期／说明时，沿用原来的直接保存方式。
2. 已有记忆点「编辑」，可修改正文、状态、说明或日期。
3. 点「更新记忆」后，展示当前内容、新内容与状态。核对目标档案、处理方式，勾选确认后才写入。
4. 只改状态也需要预览确认，不能借并存新增绕过更新；相同正文不会自动覆盖已有状态。
5. 编辑正文、日期、处理方式或核对说明后，旧确认失效，需要重新预览。取消会撤销待确认令牌，不改记忆。

新内容疑似冲突时不立即保存；预览显示可能冲突的已有内容及状态。可以选择待核实并存，或替换选中的正文。替换正文沿用原编号，旧正文留在修改历史；保存后回到待核实。

## 疑似冲突区

列表只检查当前档案的未过时记录。第一版使用本机有限规则，例如：

- `我喜欢咖啡` 与 `我不喜欢咖啡`。
- `居住城市：南京` 与 `我住在上海`。
- 明确写出的回答语言、回答风格、称呼、工作城市、最喜欢的饮料／颜色、集合时间／地点等同一字段不同值。

`我喜欢咖啡` 与 `我喜欢茶` 不按冲突处理。规则可能漏掉同义说法，也可能把不同阶段／情境的合法记录列为疑似不同，因此不自动判定谁真谁假。没有检出不等于没有冲突。每次最多展示50组，数量超限会提示。

每组展示两条正文、状态、日期、说明，可选：

- **保留其中一条为有效，另一条过时**：填写核对说明，先预览两条状态的变化，再勾选确认。两条记录同一事务更新，原内容、编号和历史保留；不会删除旧记录。
- **两条均待核实并存**：同样先预览确认；仍会保留疑似冲突提示，不把“确认并存”当成已消除事实矛盾。

取舍只影响预览的两条；若同一事项还有其他不同说法，需要继续检查。记录或档案在确认前变化会拒绝旧预览。预览有效10分钟，绑定档案与完整记忆版本，一次成功确认后不可重复使用。

## 回答与依据

个人查询默认排除过时记录，勾选「同时查询过时记忆」或明确提到过时／旧版／旧记录／历史记忆时允许回顾，显示相应状态提示。模型声明引用仍需人工核对，不因编号合法就证明结论正确。

检索命中疑似冲突时，程序会把相关的不同说法一起列出，提示无法选定当前情况，不让模型代替用户取舍。列表会补充匹配的冲突伙伴；超出上下文容量时提示未列全并引导后台核对。普通聊天询问相关个人情况时也使用此保护。

回答依据显示状态、说明、事件日期、来源、保存时间。历史版本不当作当前记忆检索；过时记录仍保存在原列表和历史中。个人原始资料文件没有新增归档，本功能保留的是记忆正文与修改历史。

个人记忆仍只用本机回答模型；已有云端发送限制保留。切换档案、刷新记忆或更改状态会清空页面的旧依据，检索缓存按版本失效，生成过程中变化会拒绝旧回答。

## 导入导出和历史

沿用个人记忆v1 JSON，新增可选 `status`、`status_reason`、`event_date` 字段。旧文件缺字段时按待核实导入；新导出保留状态。文件声明为有效／过时时须包含说明，预览会显示状态与日期；导入不是系统核实。

相同正文继续去重；若文件状态／日期与当前记录不同，预览提示保留当前状态，不覆盖。文件内重复沿用原来的首条去重规则。疑似冲突导入仍需额外确认并存，既有档案、声纹和其他记忆不被替换。旧版本软件不保证保留新增状态字段。

修改历史新增状态、说明、日期的前后值，与正文和状态更新同事务保存；过时不会清除历史。仍沿用原有个人删除行为：删除一条记忆会连同其个人修改历史删除，此次没有新增个人回收站。

## 可直接照做的文字验收

在单独的测试档案中输入虚构资料：

1. 保存 `居住城市：南京`。
2. 再保存 `我住在上海`，应先提示可能冲突；选择待核实并存并确认。
3. 问 `我的居住城市是什么？`，应列出两种说法，不擅自确定。
4. 在疑似冲突区选择南京那条有效、上海那条过时，填写说明，点击预览。此时两条仍未改变。
5. 勾选确认后再问，当前查询只使用南京；过时筛选仍能找到上海及历史。
6. 勾选查询过时记忆，问 `旧版记忆里，我住在哪个城市？请只根据过时记录回答。`，应按旧记录回顾并提示过时。
7. 把南京那条正文改为 `居住城市：杭州`，预览应显示回到待核实；确认后再查，应出现尚待核实提醒。
8. 切换另一测试档案问同样问题，不应出现前一个档案的城市。

本轮真实模型测试只验证以上小样例，不代表整体检索、语义冲突或历史推理准确率。未进行录音、播放、声纹重录或音量调整。

## 实现与自动测试

- `personal_state.py`：状态／日期校验、有限事项规则、成对冲突列表。
- `memory_review.py`：正文／状态预览、取消、成对状态确认及事务历史。
- `memory_store.py`：兼容迁移、状态读写、导入导出、缓存失效。
- `personal_retrieval.py`：状态过滤、依据提示、疑似冲突安全回答及版本复核。
- 原 `/api/memory/save`、`review/confirm` 扩展状态参数；新增 `conflicts`、`conflicts/preview`、`conflicts/confirm` 和 `review/cancel`，沿用本机 Host／Origin 限制与档案范围。
- `python -m unittest discover -s tests -p test_personal_state.py`：临时档案、迁移／声纹保留、状态与日期、过时编码排除、双记录回滚、并发／过期／取消、导入导出和HTTP隔离。
- `node tests/check_personal_state.cjs`：文字DOM模拟预览、明确确认、草稿失效与换档案迟到结果；不访问媒体。
