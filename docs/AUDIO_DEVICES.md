# 音频设备档位与只读自检

入口：**声音设置 → 音频设备档位与自检**。无需新增一级标签。

## 三种档位

| 档位 | 输入 | 输出 |
|---|---|---|
| 电脑内置 | 内置麦克风 | 内置扬声器 |
| ReSpeaker | ReSpeaker 麦克风 | ReSpeaker 的耳机／喇叭输出 |
| 混合 | ReSpeaker 麦克风 | 电脑内置扬声器 |

另外保留「沿用系统默认」，首次没有保存档位时维持原有通路，不擅自改为内置或其他设备。选择档位只是草稿，核对具体输入输出后点击「应用并保存档位」。已保存档位与准备选择的草稿分别显示。

设备名称可能不止一个；先按内置／ReSpeaker 名称识别，再明确选择具体设备。默认别名不作为指定物理设备保存。未知名称、未授权、设备缺失或同类设备存在多个时，不猜测目标。固件将设备命名为通用名称、浏览器隐藏设备时，可能无法自动归类，需后续核对设备标签与实际硬件。

## 不讲话也能做的检查

进入声音设置或点击「只读自检／刷新设备」：

- 查询浏览器可见输入输出、已有麦克风权限、指定输出能力。
- macOS 通过只读 CoreAudio 查询系统设备、默认输入输出、设备采样率／声道、可读取的输出静音与音量。读数未知时明确显示未知。
- 检查识别／朗读服务是否启用、浏览器是否提供录音处理接口。
- 查看最近输入／输出异常，如权限拒绝、设备缺失、不支持指定输出、设备占用、采样约束不支持、自动播放被阻止等。

**自检不调用 getUserMedia，不录音、不播放、不请求麦克风权限、不改系统默认设备或任何音量。** 音量很低或静音只作提示，不会自动提高。系统信息注明上次自检时间；设备改变后请刷新，不将旧快照冒充实时状态。

首次 Mac 自检需要 Xcode Command Line Tools 编译仓库中的 `tools/audio_devices.swift`；编译文件只在忽略的 `.runtime/`。组件缺失／超时会提示，浏览器清单仍可用。Windows／Linux 系统音频元数据尚未接入，不能把未取得读数当成正常；浏览器通路保留，真机兼容性尚待验证。

## 如何理解“当前输入输出”

页面将下面三层分开：

1. **已保存／准备使用的档位**：配置意图，不代表打开了设备。
2. **浏览器实际输入／输出**：以后用户主动录音时读取轨道实际设备、采样率、声道和回声消除报告；主动播放时核对指定输出绑定。未开始采集或播放时显示尚未验证，结束后仅显示最近一次。
3. **系统默认设备**：操作系统的默认选择，可能与浏览器指定档位不同。

采集设备可能报告44.1k／48kHz及多个声道，现有识别流仍为16kHz单声道。设备输入通道、固件DSP和实际音质需要后续语音验收。

“浏览器接受输出绑定”“完成播放”都不能证明扬声器实际出声。接线、喇叭供电、硬件静音、音量及固件仍可能影响发声。某些输出设备不提供软件音量／静音读数，页面不会据此认定正常。

## 权限与兼容性

浏览器未开放设备名称时，自检显示未知／待授权，不会偷偷打开麦克风来取得名称。等方便说话时，在原「点击说话」流程完成正常授权，再刷新设备清单。若已保存的指定档位因名称隐藏无法开启，先明确保存「沿用系统默认」，再正常授权、刷新并重新选择；权限已拒绝时需先在浏览器／系统设置中允许。

部分浏览器提供「选择输出授权（不播放）」按钮，用户主动点击后可选择输出授权；不提供该接口时按钮禁用。支持 `setSinkId` 也不代表已获授权，绑定失败仍会提示。浏览器不支持指定输出时，指定档位不会静默改用默认设备；可换支持的浏览器，或明确保存「沿用系统默认」。

接口依据：[浏览器设备枚举及权限限制](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/enumerateDevices)、[指定媒体输出与错误状态](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/setSinkId)。

## 保存与实际通路

- 偏好存于本浏览器当前站点的 `localStorage` 键 `yiban-audio-route-v1`，只含档位及浏览器设备编号。不写服务端数据库、不发给模型、不进入诊断导出或Git。
- 浏览器设备编号按站点隔离，因此 `127.0.0.1` 与 `localhost`、其他端口／浏览器需要分别核对。清除网站数据后需重新设置。
- 手动录音、唤醒、共同记忆语音及声纹录入复用同一麦克风类；指定输入使用精确设备约束，实际轨道不一致则停止。回答朗读、重新播放和音色试听复用指定输出绑定。
- 切换前需结束录音、唤醒监听、声纹录入、播放或处理中对话。其他页面更新时当前通路保持本轮选择，下次使用新档位；尚在准备中的旧操作会拒绝迟到配置。
- 已保存的指定设备消失、编号变化、权限不足、绑定不一致或浏览器不支持时明确报错，不自动重新选同类设备。设备重新出现时需明确核对并保存新编号。
- 配置损坏／不可读时停止指定操作，要求重新核对保存，不擅自换用默认设备。输出断开时停止本页播放，指定输入断开时停止该输入并交给原有交互取消流程。

## 回声与插话的验收边界

ReSpeaker 同设备档位只是通路选择，**不等于硬件AEC已生效**。固件、输出回采参考、物理接线与现场音量需实测。

混合档位的声音从电脑发出，ReSpeaker 的硬件回声参考可能不足。浏览器报告回声消除开启也不能证明实际效果；稍后应重点检查自播回采、插话误触发与打断。

## 稍后真人测试

1. 连接设备并刷新，选择档位与具体输入输出，保存。
2. 先确认低音量，再点原有「点击说话」，说一句完整的话，核对实际输入名称与识别结果。
3. 主动播放短句，确认声音确实从所选扬声器发出，再看实际输出绑定。
4. 分别在内置、ReSpeaker、混合档位验证；最后测试唤醒、插话及拔插恢复。

本轮仅做只读真实设备检查和模拟通路测试，没有真人录音、播放或音量调整。

## 开发与测试

- `GET /api/audio/devices`：回环 Host／Origin 限制；只读元数据、识别／朗读可用状态。返回筛选字段，不返回设备UID、机器型号、系统版本、内存或私密错误正文。
- `yiban/audio/devices.py`：编译与读取、3秒缓存、数量／字段限制及可理解的失败提示。
- `static/audio-devices.js`：浏览器偏好、只读检查、精确路由、真实绑定报告及失效处理。
- `python -m unittest discover -s tests -p test_audio_devices.py`：临时文件／模拟本机命令和HTTP访问边界。
- `node tests/check_audio_devices.cjs`：模拟三种档位、隐藏设备／拒绝权限、拔出、更换编号、不支持输出、配置损坏／存储失败、跨页迟到结果；使用真实录音类加模拟轨道验证约束及取消，不接触真实媒体。
