# 新安排替代旧安排（文字版）

“替代”会创建一条新记忆，同时保留旧记忆的内容、日期和原文依据。只有用户核对预览并点击确认后，新记录才标为有效、旧记录才标为过时；两者在同一数据库事务中生效。

## 怎样使用

1. 刷新助手页面，展开「家庭与团队 · 后台管理」，登录并选择空间。
2. 在原安排下点击「替代为新安排」，填写新安排完整内容、日期和替代原因／核实说明。
3. 点击「预览新旧安排」，核对新旧正文、日期、原状态、归属、作者、操作人、可见成员和修改权限。
4. 勾选已核对范围与内容，并单独勾选“新记录有效、旧记录过时并保留追溯”。存在其他冲突提示时还要单独核对。冲突检测沿用既有有限规则，不保证发现任意活动时间或地点冲突。
5. 点击「确认新安排替代旧安排」。取消、退出或过期不会生效。
6. 在新记录或旧记录下点击「查看新旧安排追溯」。旧记录曾保留原文时，可从追溯列表查看其原文依据。

也可以在「根据这个空间的记忆提问」中保持“自动选择记忆工具”开启，输入：

> 请用新安排替代秋日亲子科学活动的集合安排：改为上午11点15分在市科技馆北门集合，其他内容保持不变。

查到多条记录时先选择原安排，随后仍须人工核对和按钮确认。输入“确认”不会绕过按钮。模型生成采用局部原文替换：旧片段必须唯一定位，新片段必须逐字来自本次要求，未替换的原文保持不变。复杂表述、同一片段重复出现或模型提取错误可能被拒绝；可改成明确的“把X替代为Y”，或使用列表中的手动编辑入口。此限制不能证明模型选中了语义上正确的修改位置，仍须核对预览。

## 保留规则和权限

- 仅有编辑角色的原作者或空间管理员可以替代。普通编辑成员不能替代他人的记录，即使获得了正文修改权限。
- 新记录固定沿用原作者、当前可见范围和修改权限，操作人另行记录；此流程不同时扩大共享范围。需要调整新记录权限时，另走普通编辑与确认。
- 已被替代的旧记录只读，不可改写、重新标有效或单独删除。替代链上的记录不能单独删除，整空间删除仍按原规则处理。后续变化可继续替代当前记录，形成连续追溯链。
- 当前记录的普通编辑仍可用；改正文或日期会按既有规则变回待核实，普通编辑本身不建立新替代节点。
- 旧原文留在原记录，不复制为新安排的证明；未保存过原文的旧记录不会凭空产生依据。
- 追溯只展示当前账号有权访问的连续记录。若后续记录收窄范围，不返回隐藏记录的编号和正文；遇到无权访问的节点停止追溯，每个方向最多20条。
- 默认查询排除过时记录；历史回顾可勾选「同时检索过时记忆」。关联链的权威查看入口是「查看新旧安排追溯」，模型不会自动把所有历史链内容加入回答。询问“最初的旧安排”时，程序仅使用本轮已检索、已读取的关联链起点，直接展示原记录并单独标注程序定位引用；起点缺失或不可见时不猜测。
- “有效”表示操作人核实确认，不代表模型证明客观事实。确认立即生效；已支持[最近一次替代纠正](SHARED_RECOVERY.md)，先预览双方内容及范围再确认。预约生效、批量替代或语音替代确认尚未接入。

## 代码对接

- `yiban/memory/shared_replacement.py`：SQLite表 `shared_replacements(old_id,new_id,actor,created)`，保存一对一有向替代关系；新建记录、旧状态变化、关联、双方历史、空间版本在同一事务中提交。
- `yiban/memory/memory_agent.py`：`replace_memory_preview` 模型动作；只生成草稿，不授予写权限。手动入口复用同一套外层确认机制。
- `POST /api/shared/agent/memory/replace-preview`：`space_id,id,version,content,event_date,reason`，返回 `memory_preview`。
- `POST /api/shared/agent/memory/confirm`：原有参数加 `replacement_confirmed:true`；只能提交预览编号，正文和范围取服务端冻结值。
- `POST /api/shared/agent/memory/cancel`：撤销未提交草稿。
- `POST /api/shared/memories/lineage`：`space_id,id,version`，返回当前可见的前后关联记录。
- `static/shared-replacement.js`：手动新安排编辑与追溯列表；`static/shared-agent.js`：复用新旧预览、范围核对和独立状态转换确认。
- 预览有效期10分钟、最多128份，绑定具体登录会话及空间版本；成员权限或资料发生变化时必须重新生成。重启不保留未确认草稿。

## 验收边界

自动化使用临时数据库和脚本模型，检查取消、未确认、冻结内容、原文保留、原作者／范围、重复确认、并发草稿、权限变化、原子回滚、过时过滤及跨权限追溯。前端检查独立确认与取消、切换清理等。

实际 Mac 本机模型与浏览器使用独立虚构资料验收；具体结果见 `PROJECT_STATUS.md`。文字替代功能已接入；语音识别、声纹和扬声器不属于本轮验收。
