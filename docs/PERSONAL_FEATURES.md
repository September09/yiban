# 记忆、声纹与打断

## 开始使用

双击 `start.command`，打开 http://127.0.0.1:8765 并刷新页面。左侧展开「用户与记忆」。

### 1. 长期记忆

1. 输入名字，点击「创建」，或选择已有用户。
2. 在记忆框中写入内容并点击「保存记忆」；也可以聊天时说「记住：我喜欢简短回答」。
3. 说「你记得什么」查看已保存内容。普通聊天不会自动写入长期记忆。
4. 点击列表中的「编辑」修改已有信息，点击「更新记忆」查看前后差异，勾选并确认后才保存。也可点击「删除」，或说「忘掉：」加完整的原始内容。

5. 在「查找已保存的记忆」输入关键词，筛选当前用户的内容；旁边显示匹配条数／全部条数。清空关键词恢复完整列表。
6. 每条记忆显示保存来源、首次保存与最近更新时间，页面时间为北京时间。来源区分手动保存和聊天中的“记住”指令；编辑不改写首次来源和首次保存时间。升级前的旧记录保留原更新时间，首次时间与来源未知时明确标为未知。
7. 点击「导出文字记忆」下载 JSON 文件，包含当前档案的名称、称呼与全部文字记忆及时间／来源，不受搜索筛选影响。文件不含声纹、录音、聊天记录或其他档案的数据。可通过下方「导入文字记忆」恢复文字内容；它不是包含声纹的完整数据库备份。

编辑失败时保留输入，成功后退出编辑；删除正在编辑的条目会清空编辑框。切换档案立即清空旧列表和筛选条件，延迟返回的旧请求不会填入新档案的页面。重复保存相同内容仍只保留一条。

记忆按用户隔离，关闭程序后保留。「新对话」只清空当前浏览器对话，不清空长期记忆。
访客不保存或读取个人记忆。切换用户时清空当前对话上下文，避免沿用上一位用户的信息。
聊天时从当前用户最多 200 条记忆中，以文字重合度排序，取最多 8 条、总计不超过 2200 字作为模型背景；暂未增加向量语义检索或自动摘要。
修改偏好请编辑原有记忆；新存一条相反的内容不会自动删除旧事实。

### 修改历史与冲突确认

- 每条记忆的「修改历史」显示最近 100 次记录，包括新建、编辑、文件导入、确认替换／并存的操作时间与前后内容。数据库保留该条记忆的全部历史；超过 100 次时页面明确显示总数和展示数。
- 旧记录升级时只有“升级时已有内容”的起点；无法还原此前的修改，不伪造历史。历史时间是操作发生时间，独立于导入文件原有的首次保存时间。
- 编辑后先展示数据库当前内容和草稿。若另一窗口已经改过，显示并发变更提示；确认前再检查快照，发生新变更就要求重新预览。
- 新增、聊天“记住”指令遇到可能冲突时，先不保存，页面列出候选，可选择保留并另存（并存）或替换指定的一条；每次需勾选确认。取消不会写入。替换只更新选中的记录，其他可能冲突的记录仍保留。
- 当前规则包括相同对象的“我喜欢／我不喜欢”、简短／详细回答偏好，以及“称呼：”“居住城市：”“回答语言：”“回答风格：”的不同取值。规则不做模型推理，不能识别所有矛盾、时间变化和复杂语境；普通相似文字不自动视为冲突。
- 聊天触发冲突时会回复“尚未保存”，并展开左侧确认面板；确认后当前正文才进入后续对话检索。选择并存意味着两种说法都可能被检索，建议在确认时根据实际情况整理。
- 删除记忆会同时删除其全部历史；删除档案会级联删除该档案的记忆、历史与声纹。程序之外的旧备份不随之删除。历史不进入模型上下文、不包含在文字 JSON 导出中，也没有一键恢复旧版本功能。

### 文字记忆导入与确认恢复

1. 在「当前用户」选择目标档案；导入不会按照文件中的档案 ID 自动选择人，也不会新建或重命名档案。
2. 展开「导入文字记忆」，选择忆伴导出的 v1 JSON 文件，点击「预览导入」。支持最多 2 MB、200 条，每条 1–1200 字。
3. 核对原档案、恢复目标、将新增的文字、已有重复和文件内部重复。预览只读取和比较，不写入数据库。
4. 若预览列出可能冲突的内容，还需单独勾选“确认并存”；不希望并存时取消导入，先整理文件或现有记录。勾选确认后点击「确认恢复」。只新增非重复文字，保留已有内容、称呼和声纹；导入记录生成新 ID，原来源／首次保存／更新时间沿用文件记录。导入元数据是文件提供的信息，不代表事实已核验。
5. 成功后列表和条数刷新。再次导入同一文件会跳过已存在内容；全是重复或文件为空时不提供恢复操作。

去重仅比较去掉首尾空白后的完全相同文字，区分大小写、标点和内部空白。相似内容、矛盾说法不会自动合并或覆盖，需要用户编辑整理。合并后超过每人 200 条、文件格式／内容／时间无效时整批拒绝，不会悄悄截断或部分导入。

预览与选定目标、文件内容和目标当时的记忆状态绑定，有效期 10 分钟。切换用户、重选文件需要重新预览；预览后其他窗口修改了目标档案／记忆，或服务重启，确认时会要求重新预览。确认后的批量写入在单个数据库事务内完成；失败回滚整批。预览内容只暂存在服务内存，原文件不会上传到云端模型或保存进项目。

当前仍为本机原型，手动选择档案不是账号认证。共同记忆另有独立空间账号和成员权限，见 [共同记忆说明](SHARED_MEMORY.md)；个人记忆不会自动共享。

### 2. 声纹识别

1. 选择自己的用户档案，展开「录入或删除声纹」。
2. 由本人勾选保存声纹的同意选项。
3. 按提示录制三段不同内容的语音，每段约 6–10 秒；每段可手动结束，最长约 10 秒音频。
4. 点击「保存声纹」。只有保存成功才写入特征；原始录音只短暂存在浏览器和服务内存中。
5. 勾选「用声纹自动识别本轮说话的人」，再用点击录音或语音唤醒提问。

每次完整提问结束后匹配已录入档案。达到匹配阈值且领先第二候选足够多时，切换到匹配用户；声音过短、模型不可用或不确定时按访客处理。
声纹未确认前不会因为上次选过某人而继续读取那个人的记忆。文字输入使用当前手动/匹配选中的档案。
关闭自动识别后可手动选择档案。声纹用于个性化对话，不是登录认证，也没有活体或录音重放检测。

默认相似度阈值 0.65、候选差值 0.08 是初始调试参数，不能当作准确率保证。真实多人、噪声、不同麦克风和远场效果需要实测校准。
建议在将来实际使用的麦克风上重新录入，保持只有一个人说话。
录入需每段至少约 2.5 秒有效语音；识别需约 1.2 秒有效语音，因此特别短的指令可能被判为访客。

模型：Sherpa-ONNX 官方发布的 `3dspeaker_speech_eres2net_base_sv_zh-cn_3dspeaker_16k.onnx`，本地文件 `models/speaker.onnx`，约 38 MiB，512 维特征。
本次下载文件 SHA-256：`1a331345f04805badbb495c775a6ddffcdd1a732567d5ec8b3d5749e3c7a5e4b`。
模型指纹随特征存储；更换模型后，旧特征不会被用于新模型匹配，需要重新录入。
来源：[官方模型发布](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models)、[官方 Python 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/speaker-identification.py)。

### 声纹匹配后的首次称呼

在「用户与记忆」选择档案，填写「首次问候称呼」并保存，例如“王先生”“李女士”或“小王”。留空使用档案名，不根据声音判断性别。已有声纹不需要重新录入。

本次页面会话中，每位用户首次通过点击录音或唤醒语音成功匹配，并收到回答时，文字与朗读前会加上“称呼，你好。”。同一会话后续不再由程序重复添加；甲乙轮流讲话分别计数，短暂拒识后再次匹配也不重复。文字发送或仅手动选择档案不会触发声纹问候。点击「新对话」或刷新页面后重新计数；没有收到回答的失败请求不会消耗首次问候。

### 3. 打断

- 随时点击「打断 / 停止」：取消当前生成/合成、停止播放；如果在手动录音，也会停止并丢弃这次录音。
- 开启语音唤醒并勾选「唤醒开启时允许插话打断」后，在思考或朗读阶段直接说新问题，不必再次说唤醒词。
- 检测到说话开始时立即停止旧回复，保留当前音频继续收音，等说完后进入新一轮。
- 关闭唤醒或取消插话选项，就不会在回答期间自动监听。页面加载时不会自行申请麦克风权限。

第一轮请戴耳机测试，避免扬声器声音重新进入麦克风。浏览器已请求回声消除，但实际支持和效果因设备而异。
ReSpeaker 的声音输出、回声参考和声道仍需真机调试。当前没有 USB 直采、ESP32 音频入口或硬件 AEC 配置程序。
取消会关闭本程序的模型连接，并停止 Mac 合成子进程；外部模型服务是否立即停止设备计算，取决于该服务的断连处理。
当前语音仍按整句合成，没有实现逐词流式 TTS。声纹识别在一句话结束后发生，不是逐帧分离多人说话。

## 数据与维护

### 声音识别诊断

页面左侧有「声音识别诊断 · 最近 10 步」，显示本次是文字发送、点击录音还是唤醒提问，以及实际麦克风、录音总时长、VAD 有效语音时长、最高相似度和拒识原因。相似度不是准确率；dBFS 是音频电平，不是环境声压分贝。

输入框「发送」只发送文字，不采集声纹。需要使用「点击说话」或语音唤醒测试。有效语音不足、相似度不足、候选太接近、没有兼容声纹会分别说明，不能仅凭 HTTP 200 判断识别成功。

服务器诊断日志为 `.runtime/speaker-diagnostics.jsonl`，每行一条 JSON，时间为 UTC；页面日志编号可对应 `trace_id`。单文件约 256 KB，最多保留两个轮转备份。不记录录音、聊天正文、姓名、档案 ID 或声纹向量。页面的设备名称仅在本页面显示，不写入服务诊断日志。刷新页面会清空页面内最近步骤，服务器日志仍保留。

语音中“看看能不能认出我的声音”等表述不会再被当成拍照请求；明确提到照片、摄像头等的看图请求保持原有行为。

- SQLite：`data/assistant.sqlite3`；`profiles` 保存档案、`memories` 保存当前记忆、`memory_history` 保存修改历史、`voiceprints` 保存声纹特征。文件权限设为仅当前系统用户读写，未做数据库加密。
- 数据：用户档案、明确保存的文字记忆、本人确认保存的声纹向量及模型指纹。不存原始声纹录音或摄像头照片。
- 「删除声纹」保留文字记忆；「删除当前用户」同时删除该用户的文字记忆和声纹，并清除当前浏览器对应历史键。系统备份及其他浏览器副本不在此操作范围内。
- 数据目录已加入忽略清单。备份/拷贝整个项目时会包含这些个人数据，应由用户决定是否携带。
- 声纹计算在本机。当前默认模型也在 Mac 本地；如果配置远端模型服务，被检索的文字记忆会作为对话背景发送到该服务，声纹向量不会发送。
- 服务仍只监听本机，没有增加局域网公开访问或身份认证功能。

## 开发入口

| 文件 | 职责 |
|---|---|
| `yiban/memory/memory_store.py` | 用户、明确记忆指令、检索、声纹向量存取 |
| `yiban/audio/speakers.py` | 有效语音检查、特征提取、匹配与拒识 |
| `yiban/turns.py` | 每轮取消信号、提前取消记录 |
| `yiban/audio/voice.py` | 唤醒、断句和插话事件，保留插话音频 |
| `yiban/backends/models.py` | 可取消的模型连接 |
| `yiban/backends/speech.py` | 可取消的 Mac 合成子进程 |
| `static/personal.js` | 用户与记忆管理、三段声纹录入 |
| `static/app.js` | 监听切换、停止播放、取消请求与旧回复隔离 |
