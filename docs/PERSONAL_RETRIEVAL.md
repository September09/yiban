# 个人记忆语义检索（文字第一版）

## 使用

刷新页面 → 个人记忆 → 选择当前用户 → 展开“查询个人记忆” → 输入问题 → 询问个人记忆。例如保存“我放松时喜欢去湖边慢跑”，可以问“我用什么运动方式解压？”。回答下区分模型声明的实际引用与其他候选，列出记录正文、首次保存、更新时间与保存来源。

没有匹配资料时直接提示当前档案没有相关依据，不调用回答模型。资料匹配但模型没有给出可核对引用时，提示依据不足或引用未核对，不把未引用内容充作证明。引用编号有效也不保证事实判断一定正确，仍需人工核对。

普通陪伴聊天也使用本轮相关个人记忆作为背景，并可展开“个人记忆检索”查看候选；这里不会宣称已核对实际引用。普通聊天还可使用最近对话及通用知识。希望只根据已保存资料回答，请用个人记忆查询入口。

查询是只读操作，不新增或修改记忆，也不自动朗读。停止、换档案和新对话会取消在途查询并清理本轮依据；依据不写入浏览器历史，重新打开页面须重新查询。普通聊天文字仍沿用按档案保存的最近30条历史。

## 检索与隔离

复用当前本机Qwen3-Embedding 0.6B与文字混合检索配置。先从SQLite读取当前档案现有记录，再送入向量模型；不编码或检索其他档案、共同空间、声纹或修改历史。每次最多8条以内、正文合计2200字；实际条数由配置及相关度门槛决定，不凑满数量。

派生索引使用 personal:档案ID，与 shared:空间ID 分开；索引包含模型指纹、正文哈希及历史修订号，不存正文或问题。修改／删除通过现有写入入口使对应索引失效；档案删除清理其命名空间。查询期间发生修改或删除，会拒绝旧结果并清理迟到索引。

向量服务不可用时退回有门槛的文字检索，页面提示回退；停用检索配置时也保留有门槛的文字检索。不同说法在文字回退中可能查不到，不会扩大到其他用户来补答案。未找到相关个人记忆时，普通聊天仍可继续，但不会将无关长期记忆加入背景。

个人记忆查询使用当前档案与记忆快照，模型生成后复核。普通聊天若使用个人记忆候选，先完成本轮生成并复核，再交付，可能增加首字等待；无候选时保留原流式聊天。每轮诊断记录检索策略、耗时、命中数与回退情况，不记录记忆正文。

## 边界

个人档案选择用于本机个性化，不是安全登录或声纹身份认证；共享权限继续使用独立空间账号，个人聊天不会自动读取共同记忆。个人记忆仅在本机模型档位回答；云端档位会拒绝个人记忆问答及选中了个人档案的普通聊天。若要使用云端普通聊天，需要先切为访客；切换时不会自动发送此前本地聊天历史。向量服务仍限定本机地址。

个人记忆已支持pending／valid／outdated状态；默认排除过时记录，疑似冲突先列明不同说法，见[状态与冲突说明](PERSONAL_STATE.md)。有效为操作者标记，不等于系统证明。也未为个人记忆新增活动原文归档、通用语义冲突判断或无限上下文。历史内容不作为当前事实参与检索；现有保存、编辑、冲突确认和导入流程保留。

## 对接与检查

- yiban/memory/personal_retrieval.py：档案快照、相关度检索、只读回答、引用核对与结果复核。
- POST /api/memory/search：profile_id、query及可选turn_id，返回当前档案匹配记录与检索元数据。
- POST /api/memory/ask：同参数，返回answer、sources、answer_source_ids及source_usage；客户端不能提供候选来扩大查询范围。
- server.py普通聊天附带personal_memory候选元数据，原有命令、时间、身份、图片和固定动作路由保留。
- static/personal-retrieval.js：个人查询、依据分组、停止与档案切换清理、普通聊天候选。
