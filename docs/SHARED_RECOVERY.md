# 共同记忆误操作恢复（文字版）

本轮提供共同记忆的回收站、历史内容恢复、最近一次替代纠正。操作统一经过“选择 → 填写原因 → 预览前后内容及范围 → 双重确认 → 生效”，确认前不写入。个人记忆与语音恢复不在本轮范围内。

## 怎样使用

### 误删除：回收站

1. 在共同记忆库的普通记录下点击“移入回收站”，核对正文、历史和原文保留提示，再确认。
2. 点击记忆库顶部“回收站与恢复记录”，或到“备份与恢复 → 误操作恢复 → 刷新回收站”。
3. 点击“准备恢复此条”，填写原因，点击“预览本次操作”。
4. 核对原正文、事件日期、归属、作者、状态、现有成员可见范围及修改策略；有原文可展开查看。
5. 勾选前后内容及权限两项确认，再点“确认执行本次操作”。成功后回到记忆库。

移入回收站后不参与列表、检索或问答，正文、全部修改历史和已保存的原文仍在本机保留。恢复沿用原记忆编号、作者与首次时间，递增版本并追加恢复历史；状态转为待核实。指定可见账号中已移除的成员会列明并剔除，不重新加人；全体成员范围包含现任及以后加入的成员，预览中明确显示。

### 误修改：历史内容恢复

1. 在记忆库点击“查看共同记忆历史”。页面展示最近100次历史及总数。
2. 在需要的历史内容下点击“准备恢复此历史版本”。正文、日期及来源说明均相同的版本不提供恢复按钮。
3. 填写恢复说明并预览：对照当前与历史正文、日期和来源说明，核对当前可见范围及修改策略。
4. 双重确认后生效。原来的修改历史继续保留，本次追加为新版本，记录恢复说明。

只恢复正文、事件日期和来源说明，当前作者、可见范围与修改权限保留，状态转为待核实。历史里的“全体可见”或“有效”不会自动覆盖当前设置。原文依据仍是此前已保存的依据，内容不一致时沿用原文面板的变化提示，不伪造新的证明。

### 误替代：新旧安排纠正

1. 找到当前安排，点击“纠正上次替代”。
2. 填写原因，预览两条记录的前后正文、各自范围及状态变化。
3. 确认后只撤销这一次替代关系：旧安排转为待核实，误产生的新安排转为过时。双方正文、日期、原文及历史保留，各自现有权限保留。
4. 在“查看恢复与纠正记录”可看原关联双方、操作人、时间、原因和前后状态。

连续 A → B → C 时，先纠正最后的 B → C，A → B 继续保留。不能跳过后续安排撤销较早的一段。新安排后来修改过的正文也会保留，不会被纠正流程删掉。当前不支持重新连接到任意另一条安排，或批量反转整条链。

## 权限、取消与重复操作

- 仅仍在空间中的原作者（有编辑角色）和管理员可操作。一般编辑成员即使能改正文，也不能恢复他人的历史或查看其回收站。替代纠正须同时有权管理两端。
- 回收站及恢复记录每次读取都核对现有成员与角色。操作记录的内容和范围政策为当时快照，展示名单按现有成员显示。涉及任意一端已无管理权限时，整条操作记录不返回。
- 预览绑定登录会话、空间版本及记录版本，10分钟有效，全机最多4份，同一会话只留最新一份。改原因、取消、换空间、退出及刷新会清理页面预览；未完成预览不跨服务重启保留。
- 资料或成员权限变化后需重新预览。可能冲突需额外确认；冲突检测是既有有限文字规则，不能代替事实核实。
- 确认只发送预览令牌和勾选项，不能从确认请求覆盖已预览正文。一次写事务提交正文、历史、依据、关联和操作记录；失败整批回滚。
- 已完成的同一确认可安全重试，包括服务重启后；不会重复恢复或覆盖后来又修改的内容。取消只放弃尚未执行的操作，已经生效的内容需重新选择历史或纠正流程。

## 保存方式与边界

沿用本机SQLite主库，增加 shared_trash、shared_recovery_events、shared_recovery_targets。回收站保存原记录、完整历史与原文快照；操作记录保存原因、前后内容与被纠正的关联，确认凭据只存摘要。回收站与恢复记录不进入模型上下文或浏览器长期存储。

每空间回收站最多100条或24 MB，不自动清理；超过时拒绝移入，原记录保留。有效记忆仍有200条上限，满额时不能恢复。当前没有永久清空按钮或批量恢复，达到容量上限需先整理空间；不自动丢弃旧资料。

新流程保护启用后的单条共同记忆删除；升级前已物理删除的资料不能凭空恢复，可从先前备份恢复到新空间。替代链上的记录仍不能单独移入回收站。整空间删除会删除其回收站和恢复记录，无法从本回收站恢复整个空间，应事先保留空间备份。

现有空间JSON备份导出正常记忆、完整历史和当前有效的替代关联，不包含回收站快照和独立恢复审计表。需要跨电脑保留的回收站资料应先确认恢复再导出。记忆历史中的恢复类型与原因会随备份保留；已撤销的关联可在原库恢复记录查看，未做专门跨电脑重建。
