# 第二版结构化记忆

个人与团队共用候选协议 `yiban.memory-candidates.v2`，使用新表 `memory_v2_*`。不自动迁移旧记忆；旧账号、空间、权限、原文和历史保留。对话页可选择新版或旧版资料，新版默认使用新版数据。新旧格式不相互拼接，也不把旧的文字条目数量当作新版事件数量。

## 使用

1. 在“账号与空间”登录，再进入“记忆库”。新版个人记忆属于登录账号；本机个人档案的名字、声纹匹配及文件里的 owner 均不授予该账号权限。
2. 选择个人或所属团队范围。个人仅自己可读；团队可选作者及管理员，或全体成员（包括以后加入者）。页面默认仅作者及管理员，修改默认仅作者与管理员。
3. 读取新版JSON，或已有的cards候选JSON。转换只提取候选，不读取文件中记录的电脑路径。可提供原始文章核对摘录；没有原文时保存的依据明确标为“候选文件”，不冒充原始文章。原文件中的 public、owner、confidence、needs_review 均不直接决定权限与核实状态。
4. 核对人物、事件边界、日期和事实。必要时在“查看／调整候选文件”中调整并重新校验。私人候选不能直接发到团队，请先存入个人范围；需要共享时另行整理脱敏后的候选。
5. 勾选需要的记忆，预览归属、权限、完整内容和待核对问题，确认后才写库。选择文件、校验、预览均不写库；预览10分钟有效且绑定账号、范围、成员权限与资料版本。
6. 在前面对话选择“当前记忆库”，自动查询登录账号自己的个人记忆及有权查看的团队记忆；也可仅个人或指定团队。新版查询目前仅文字，不自动朗读。新库为空时不会自动回退旧资料。

已增加MD自动提取入口，先准备候选、分列私人内容并审阅脱敏全文，再沿用预览与确认入库。自动提取不替人确认事件边界、年份、人物身份、任职、数量口径或隐私是否完整移除。详见下方v50流程。

## 简短文字记忆

“记忆库 → 1 · 添加记忆”支持可选标题与最多1200字符的内容。先点“生成候选，尚不保存”，再“查看保存预览”，最后明确确认保存。保存后为待核验，可在快速核验中对照输入原文，点击“确认正确，下一条”。修改输入会使旧候选和保存预览失效，需重新生成。

此入口把输入原样保存为quote候选与manual来源，校验UTF-8 SHA256和精确字符位置；不调用模型，不推断人物、事件日期或结构化事实，不声称已自动脱敏。生成候选不创建入库计划、不写库；预览和确认继续使用现有权限、版本与去重规则。团队只读成员不能准备写入候选，个人范围只属于当前账号。

对话默认自动查询账号个人与有权查看的团队记忆；账号没有团队时也会查询个人范围。访客无需登录可以聊天；“普通聊天（不查账号记忆）”可用于已登录后的闲聊。声纹与称呼档案不授予账号权限。

## 协议与数据边界

可运行的虚构样例：[memory-v2.synthetic.json](../examples/memory-v2.synthetic.json)。校验唯一实现位于 `yiban/memory/v2_schema.py`，不维护另一套松散字段映射。每包最多200条、500个人物／组织、200个事件、20份来源；单来源20万字、来源合计40万字。UTF-8、严格字段白名单；未知格式版本或未知字段拒绝，避免静默丢数据。

| 对象 | 字段与含义 |
|---|---|
| 包 | schema、batch_name、sources、entities、events、records |
| 来源 | key、name、kind（original/candidate/manual）、text、sha256、published_at、url；不接受路径指令 |
| 人物／组织 | key、kind（person/organization/character）、name、aliases；名字不是账号，不跨资料按同名自动归一 |
| 事件 | key、kind、title、time、state、location、parent_key；kind示例meal/basketball/birthday/hiking/competition/training；state为held/planned/cancelled/unknown |
| 记忆 | key、type（event/fact/quote/reflection）、title、summary、detail、participants、event_key、fact、emotions、tags、verification、verification_reason、sensitivity、confidence、evidence |
| 时间 | raw、start、end、precision（day/month/year/range/unknown）、basis（explicit/inferred/unknown）；未知用null，不补造年月日；开放范围end可为null |
| 原文引用 | source_key、start、end、text；位置按Unicode字符、左闭右开，对全文SHA256和精确摘录同时校验 |
| 结构化事实 | subject_key、object_key、predicate、value、unit、metric、term、effective；主体编号必须存在 |

事实predicate只接受已注册的holds_role、quantity、score、relationship、preference、statement。扩展类型须同时增加校验、展示、查询与测试，不允许任意字段无约束进入模型。

- 任职：holds_role，value为职务，term为届次，effective为任职有效时间。旧任职继续作为历史事实保留；问现任仅在明确有效时间覆盖查询日时认定，否则列出已记录届次并说明不能确认现任。
- 数量：quantity，value为非负有限数字，unit与metric必填。征集、筛选和送达是不同口径，不自动选择其中一个覆盖其他值。
- 比分：score，object_key为对手，value为 `{own,opponent,result}`；缺失比分用null，未知胜负用unknown，拒绝比分与胜负矛盾。
- 关系：relationship必须指定双方。character表示角色实体，不得推断为现实人物亲属关系，更不授予权限。

同一范围内key稳定，建议提取时生成带资料命名空间的编号。相同实体／事件／来源编号必须有相同内容；冲突会阻止导入。相同记忆编号、相同内容再次导入跳过，不覆盖旧记录。同一天可有多个事件；多份报道应明确关联同一event_key。转换器生成的跨文章同名人物不自动合并，需审阅后明确统一编号。同名事件只作重复提示，不自动归一。

verification（pending/confirmed/disputed）与生命周期（active/archived）、事件发生状态分开。高置信度不等于已核实，confirmed/disputed需要说明。正文或结构化事实修订后回到pending；归档保留历史但退出默认问答。新旧记录替代、跨范围分享不是自动联动：发布团队版本需独立审阅，不随个人私密修改自动更新。

## 查询、修改与维护

- 查询先按账号成员身份与记录可见范围过滤，再进行结构化查询或复用本机语义检索。生成前、返回前均核对范围版本和成员状态；撤权、资料变化或取消后拒绝旧结果。个人资料不发往云端；云端只可使用团队全体成员可见资料。
- 任职、捐书数量和比分由结构化字段展示，不让模型临时凑数字。数量统计按已授权的完整事件快照和事件编号计算，分别列出个人／团队；不按搜索前几条、文章数或日期数计数。预告、取消、发生情况未知、未来事件不计入；日期推定或无法匹配查询时间的列为待核对。父子事件同时匹配同类统计时不另计父汇总。已记录次数不等于现实全部活动，也不证明团队每位成员出席。
- 记忆库支持版本化修改、核实、归档、精确原文摘录及最近50条修改历史。原文全文仅作者及所在范围管理员可取，普通成员仅能取可见记录的摘录。人物名称不会从其他隐藏条目带入。
- 可“修正关联事件”，先列出全部受影响记录；需要对这些记录均有修改权限。保存后事件元数据及全部关联记忆版本在同一事务更新，相关记录回到待核实，旧事件快照写入历史。不能只改一篇报道而让同事件其他报道悄悄保留不同日期。
- 首版使用SQLite独立表与索引，事实、参与者、证据分表；情绪、标签、时间对象等受校验的小结构以JSON保存。全文来源为不可变快照。新表由版本号守卫；未来结构升级必须显式迁移并先备份，不用启动时零散添加字段来猜测版本。
- 旧空间“备份与恢复”只处理旧版记忆，**不包含新版表**。目前新版的完整备份方式是整个SQLite数据库的一致性备份，包含新旧表、账号与历史；本轮启用前已执行。不要把旧版空间备份当成新版完整备份。

离线转换不连接数据库：

```sh
./.venv/bin/python -m tools.prepare_memory_v2 候选.json --original 原文.md --output 新版待审阅.json
```

不提供原文时省略 `--original`；命令拒绝覆盖已有输出。真实资料、候选文件、报告与备份放入data/或.runtime/，不提交Git。

接口均为POST并要求 `Authorization: Bearer ...`：`/api/memory/v2/draft`、`convert`、`validate`、`preview`、`confirm`、`list`、`evidence`、`source`、`history`、`update/preview`、`event/preview`、`discard`、`ask`。每个操作在服务端确定个人所有者或验证团队成员。主对话 `/api/companion/ask` 的 `memory_version:2` 使用新版查询；未指定的旧调用保持原路径。


## 重点审核工作台

在“新版记忆”选择团队后，重点审核列表按当前有权查看的记忆筛选数量口径、任职届次、比分与对手、姓名与归属、日期推定及事件边界提示。分类来自现有结构化字段和核实说明，不写入固定班级名单，不以规则提示替代人工判断。可按进度、问题类型及关键词筛选；“全部新版记忆”折叠保留非重点条目。

选中一条，左侧直接编辑正文、核实状态与说明，数量／职务／比分提供普通表单，右侧自动读取带记录版本校验的精确原文摘录。来源全文仍仅作者与管理员可取；读取失败或版本失效时不能直接确认。退出账号、切换空间或权限绑定变化会清理列表、编辑内容与原文缓存；迟到的原文不回填。

“确认无误”只生成保存预览，仍需在本条下方核对前后内容并确认保存；没有批量自动确认。“保留待核实”同样经预览保存；“下一条”只切换，不保存。确认后的条目从默认未完成列表退出，后续仍可切到“已确认”查看。正文或事实修改会被服务端强制回到待核实，不能借快捷确认绕过；关联日期用原有“修正关联事件”同时预览影响范围。


## 新版连续追问与快速核验（2026-11-16）

前面对话以本机短期话题标识衔接新版问题，不发送个人聊天历史。已明确的事件可带出该事件的其他授权记忆；检索同时使用标题与事件名称。追问按上轮实际引用细化物品主题，每轮重新读当前授权资料和原文摘录，不把上轮模型回答当证据。话题按登录令牌、资料版本、范围与本机/云端模式绑定，10分钟失效；新对话、切换范围或资料/成员变化会重置或拒绝旧话题。省略主题且无法确定对象时先澄清，不从其他文章猜。

物品数量未在已读取正文和摘录中记载时，会明确说明并列出依据；不能按收礼人数推算物品数。此为保守规则，复杂计数和模糊跨事件指代仍需核对。

网页“记忆快速核验”默认显示全部使用中、待核实条目，包括没有重点提示的记忆。问题、候选答案和精确原文并排显示。

- 确认正确，下一条：代表当前审核人已完成人工核验。系统沿用原预览/确认接口，自动检查权限、原文版本、记录版本与归属，只修改本条核实状态及说明；不修改正文、数字、日期、查看权限或归档状态。原文尚未读取、只读成员、已归档条目或正在编辑时不能快捷确认。
- 不正确，稍后修改：标为有争议并自动下一条，集中在“待修改／有争议”；这类记录不进入普通新版问答，保留原文、编辑与历史以便修订。
- 不确定，下一条：跳过，不写入任何改变。

正文、事实或事件日期的修改仍使用“修改答案或管理归档”中的原有对照流程；正文/事实修改后回到待核实。核验结论由人作出，权限和格式检查通过不代表系统已经证明内容真实。可下载核验表本轮未更改。

### 问句筛选与缺少资料的回答

新版问答按当前问题的届次、职务、对手、日期和数量口径筛选；短期追问只复用必要的查询目标，不把上一轮正文或答案当依据。通用序号（例如“第一届”）不作为赛事名称；并列问题保留全部目标。无对应事实时不会退回模型猜测其他届次。

无充分依据固定回答：“目前我能查看的记忆里，还没有足够资料回答这个问题，我暂时无法确认。”有相关记忆但缺少细节时，说明具体缺项；例如沙漏数量、签收数量、球员个人得分。不能把团队比分当个人得分，也不把筛选数量当签收数量。缺少或无效的模型引用也使用固定话术。

新书和二手书加总仅使用同一授权范围、同一事件、同一主体、同单位且同一口径的明确分项；重复报道去重、冲突分项不加总，总计不重复相加，不跨团队合计。计算保留操作数记录编号，引用仍指向原始分项。筛选后合计会注明不代表签收数量；不会恢复已归档合计记录。

## 新问题理解与证据约束（2026-11-16，v45）

事件匹配同时考虑名称中的有区分度词、同义问法及当前可见相关条目；“第一学年”等统计期间不单独锚定班会。进入某个活动后，按本轮所问字段选择相关记录，冠军、奖项、队长等不局限于活动概述。跨活动比较保留双方，同日晚间追问使用已解析日期，不串到另一天的同类活动。上轮条目只用于消解代词，不作为新一问的额外要求或事实依据。

物品数量保护要求明确的物品单位，不将权重、公里和原创篇数误拦。运单号码、作者和费用不进入捐书数量计算。没有明确物流号码、费用或完整出席依据时使用统一未知话术；部分同学聚餐不证明全员到齐，也不证明某人缺席。

唯一活动的名次问句，如当前全部可见记录只有一个已核验结果且原文明确支持，则返回该条当前文字，保留班级/校园阶段；冲突、多结果、未核验或否定不明时不走此路径。名次、人名、数量均不写死在检索规则中。模型只接收有预算的当前授权候选与对应摘录，避免超过本地上下文上限；完整原文仍可按原权限查看。

每轮都重新读取当前内容、引用和成员权限，返回前再次检查；没有新增答案缓存或写入通道。此次冻结30项复测为25内容题与5项权限检查全部通过，43处实际引用摘录逐字符一致；是本轮回归结果，不代表所有新问法都已验证。向量开关与默认模型没有更改。
