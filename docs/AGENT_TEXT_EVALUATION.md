# 文字 Agent 评测与回答质量改进

更新：2026-11-10。先验收文字，语音、真人声纹与设备播放另行测试。

## 现在改善了什么

1. **没有依据时不挂无关引用。** 对“资料未说明”这类纯粹的无答案回复，清除无关的实际引用；候选资料仍可以在候选区查看。混合回答中有依据的部分继续保留引用。这只是对明确无答案句式的检查，不是通用事实验证器。
2. **暂定信息同时说出具体内容和状态。** 比如“地点暂定河畔公园，但尚未最终确认”，避免只说“不确定”而遗漏资料已有的暂定地点。
3. **比较前读完候选。** 对比较、冲突、历史等问题，程序要求读完本轮已授权的候选资料后才能结束工具阶段；仍受每轮次数和超时限制。它不会绕过检索范围和成员权限。
4. **旧版与现行依据分开。** 明确只询问“旧版／过时”安排时，回答使用标记过时的记录，现行记录留在候选区；没有对应记录就说明缺少旧版依据。新旧对比会同时使用两类记录。一般的历史事件回顾不会把有效的历史事实错误当作过时记录。
5. **同名活动先选日期。** 增加对没有引号的常见活动名识别，例如“周末绘本会在……”；同名但日期不同的活动先澄清。只把明确包含唯一已知活动名的补充资料归入同一话题。复杂简称、隐含指代和所有活动名称尚未完全覆盖。
6. **冲突资料逐条展示。** 读取多条资料进行比较时，模型返回结构化的比较判断和引用编号，程序按来源展示原文、状态、日期，防止自由改写时把冲突地点说成两个场地都举办。结论明确标成“模型对照判断”，仍需核对，不自动修改任何记忆。

刷新助手网页，在共同记忆问答保持“自动选择记忆工具”开启，就可以继续用现有资料测试。不需要把本次虚构资料导入真实团队空间。

## 本轮评测结果

测试资料是新建的虚构团队与活动，不使用真实记忆数据库。16道题覆盖：换一种问法、携带物品、待核实、未知预算/接送安排、现行与旧版、成员隔离、空间隔离、非成员拒绝、同名澄清、冲突地点、无关问题、资料伪指令、明确否定事实。

| 阶段 | 规则检查通过 | 说明 |
|---|---:|---|
| 修复前首轮 | 10 / 16 | 首次模型输出全部保留；其中一项403拒绝被评测器错误视为引用缺失，修正评测器默认值后重新评分，未改模型输出 |
| 最终修复后回归 | 16 / 16 | 重新运行真实本地 qwen2.5:3b，按同一冻结资料和题目检查 |

**16/16 不代表整体回答准确率。** 这是开发者编写的虚构小样本，规则主要检查关键事实词、期望引用、状态提示、权限及是否意外写入。它不能充分理解否定、因果与所有语义错误。修复后使用同一套题，属于回归，不能再称为未见过的盲测。

逐题查看时曾发现：一版回答通过了关键词规则，却把冲突地点说成“在A和B举办”。本轮因此增加了程序生成的逐来源原文对照，而没有仅凭规则分数结束验收。最终报告保留“待人工核对”的提示，尚未进行独立人工标注或真实业务准确率评估。

本地完整测试：259项后端检查和前端逻辑检查通过。测试使用临时库与模拟服务；本轮模型文字评测另调用本机 Ollama。没有录音、播放声音或调整系统音量。

## 如何重复运行

先按项目说明启动本机模型服务，然后在项目根目录执行：

```bash
./.venv/bin/python -m tools.evaluate_agent \
  --output .runtime/evaluation/my-text-check \
  --label "本机文字回归"
```

输出目录必须是新的，工具不会覆盖旧结果。默认读取 `config/mac.json` 的模型和检索配置；**不会打开其中配置的主记忆数据库**。账号、空间、记忆、诊断与向量缓存都在一次性的临时目录生成，结束后清理。只支持本机 Ollama，远端/云端地址会拒绝运行，避免无意把测试资料发到外部或消耗云端额度。

输出文件：

- `index.html`：可直接打开、发给成员阅读的逐题报告。
- `report.json`：最终结果、数据集与代码指纹、引用、工具轨迹、耗时和用量。
- `progress.json`：每完成一题就保存的进度；中断时不能将它误当完整报告。

任何规则未通过，命令返回非零退出状态。真实模型评测不放入日常自动测试，避免每次检查都启动模型推理；`tests/run_all.py` 运行隔离的可重复回归。

要扩充题目，可以用 `--dataset` 指定遵循同一格式的虚构资料文件。先冻结预期事实和引用，再运行；不要看到回答后仅为提高分数而修改期望答案。新增数据集用新的版本名，保留前一版报告。

## 报告怎么看

优先逐题核对这五项：

1. 回答是否真正回答了问题，而不是只出现了几个关键词？
2. 实际引用是否支持所说的事实？候选资料不能直接算引用。
3. 待核实、过时和冲突是否仅限定到对应的记录？
4. 缺少资料时是否明确说不知道，而不是编造或拿无关事实代答？
5. 不同成员是否只能访问自己有权限看到的记录？查询是否没有产生记忆写入？

报告中的状态码来自业务函数对应的权限/请求状态；这套模型评测直接调用业务模块，不是浏览器端到端测试。浏览器、HTTP路由与界面逻辑由已有回归分别覆盖。
